# ADR 0001：项目知识随代码维护

- 日期：2026-10-02（Asia/Shanghai）。
- 状态：用户已首次确认知识库交付，全量复核通过，等待二次确认。实时确认进度统一见文末链接的当前状态。
- 来源：本聊天讨论跨聊天接续项目与业界方法，提出 Docs as Code + ADR + 当前状态后，用户回复“ok”。
- 首次确认依据：2026-10-02，本聊天中用户对具体知识库交付回复“确认”；全量复核未改变既定方案。

## 背景

聊天不能作为唯一项目记忆。仓库已有需求、设计、测试报告、任务计划及进展记录，但早期摘要与最新代码存在差异。接手者需要能快速定位当前事实、验证证据及历史原因。

## 决定

1. 在项目仓库内使用 Markdown 保存知识，与相关代码一起评审和版本管理。
2. `AGENTS.md` 保留长期规则并指向知识库入口；`docs/README.md` 维护索引与更新约定。
3. `PROJECT_STATUS.md` 是当前工作状态的主要维护位置；历史任务计划和进展日志保留为历史资料。
4. `docs/项目概览.md` 提供功能、技术栈和模块定位；已有需求、设计及测试报告继续复用。
5. 重要决策用递增编号 ADR 单独记录；重复问题继续使用 `problemMemory.md`。
6. 每次接手核对代码基线与工作区，每次结束更新状态、下一步及证据；明确区分历史记录、实现存在、测试通过和用户确认。

## 影响

- 可跨聊天、跨开发者恢复上下文，并追溯文档与代码变化。
- 需要持续维护，过期记录不能当作当前事实。入口和当前状态保持简短，详细资料按需读取。
- 暂不增加外部知识库、数据库或检索服务依赖。后续确有规模需求时再评估。
- 文档纳入 Git 不等于允许夹带用户改动、提交敏感内容或跳过项目阶段确认。
