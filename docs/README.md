# 项目知识库

本目录是 MySMSCode 的知识入口。采用 Markdown + Git 管理，复用已有需求、设计和测试资料；当前工作状态只维护在 [PROJECT_STATUS.md](../PROJECT_STATUS.md)。

## 接手顺序

1. 阅读 [项目规则](../AGENTS.md)，再阅读 [当前状态](../PROJECT_STATUS.md)。
2. 执行 `git status --short`、`git log -5 --oneline`，对照状态记录的提交基线和未提交改动。只检查与当前任务相关的变化，避免重复全量扫描。
3. 按任务阅读下表资料及相关代码。文档描述与代码不一致时，核实差异：代码说明当前行为，需求与决策说明预期行为。
4. 延续有证据的确认与授权。历史确认缺少来源或适用版本不明时标为待核实，不能凭旧文档中的“已完成”推断所有阶段已获批准。

## 维护约定

- 一个事实指定一个主要维护位置，其他文档链接引用。签名要求以 AGENTS.md 为准，不在各文档复制证书和本机配置。
- 与代码变化相关的文档同步检查；有 Git 提交时将相关文档纳入评审和版本管理，不夹带用户原有改动。
- 状态必须区分：已实现、验证通过、验证失败、未验证、历史记录。测试源码存在不代表测试通过；旧版本通过不代表当前版本通过。
- 验证记录注明日期（本项目用户时区为 Asia/Shanghai）、提交编号、相关未提交改动、环境、执行命令、结果和证据位置。无法取得的字段明确写“未记录”。
- 用户确认注明对象、版本或范围、原话摘要和来源。阶段切换仍按 AGENTS.md 执行；知识整理不代表批准后续开发或部署。
- 每次结束更新当前状态中的下一步、阻塞点、待确认事项。历史日志按日期追加，当前状态保持精简，不复制全部聊天。
- ADR 一篇记录一个重要决策，包含背景、状态、决定、影响和依据。被替代时保留原记录并链接新记录；追溯整理的旧决策明确标注“历史整理”，不能编造过去的确认。
- 不写入密钥、密码、真实 Webhook、短信正文或不必要的设备及个人信息。需要举例时使用占位符。
- 搜索优先限定 `app/src`、`docs`、根目录文档和 `gradle`；排除 `.gradle-user-home`、`.gradle`、`build` 等生成目录。

## 验证与资料更新

本次仅建立文档入口和接续状态。检查 Markdown 本地链接、Git 差异和代码引用；应用构建、自动化测试、真机验收分别记录，不能以文档检查替代。

后续新增 ADR 可沿用 [0001](adr/0001-项目知识随代码维护.md) 的结构，使用递增编号。只有实际需要时再补充教程、操作指南或架构图。
